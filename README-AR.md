# سنتات iOS 9.0.3 — مشروع بناء IPA من ويندوز

**الحالة:** مشروع iOS أصلي بلغة Swift مع WebKit، مستخرج من ملفات Android 9.0.3. **ليس ملف IPA جاهزًا للتثبيت.** ملف IPA الذي ينتجه GitHub Actions سيكون **غير موقّع**، ويلزمه توقيع Apple قبل استخدامه على جهاز iPhone. لا يمكن بناء تطبيق iOS أصلي والتحقق منه باستخدام ويندوز وحده دون بيئة macOS؛ لذلك يستخدم المشروع GitHub Actions على جهاز macOS سحابي.

## ما نُقل من النسخة الأصلية

- رابط التطبيق `https://sntat.app/`، فتح الموقع داخل WKWebView.
- فيديو المقدمة **الأصلي من النسخة المرفوعة** لمدة **5 ثوانٍ** بالصوت نفسه وخلفية فاتحة؛ يبدأ عند التشغيل البارد فقط.
- صورة التطبيق الأصلية بحرف S الفيروزي/الحليبي، بصيغة أيقونة iPhone 1024×1024.
- حفظ Cookies وlocalStorage وبيانات WebKit عبر `WKWebsiteDataStore.default()` دون مسح عند الخلفية/العودة. **لا توجد طريقة تلقائية لنقل جلسة Android القديمة إلى iOS**، وقد يتطلب أول تشغيل تسجيل الدخول مجددًا. إنهاء الجلسة من الخادم يبقى بيد الموقع.
- فتح روابط واتساب وتليجرام وفيسبوك بالتطبيقات الخارجية/Universal Links عندما يدعمها نظام iOS، بالإضافة إلى الرجوع للتطبيق يدويًا بعد نسخ الكود.
- السماح للصفحات الموثوقة على `sntat.app` فقط بطلب كاميرا وميكروفون عبر WebKit وطلب إذن النظام.
- منتقي الملفات الموجود في WKWebView، تنزيل الملفات المدعومة ومشاركتها، تنبيهات JavaScript داخل التطبيق، رسالة انقطاع الإنترنت مع إعادة المحاولة.

## فروقات مهمة عن أندرويد

- **الإشعارات:** Firebase Android ليست APNs iOS. الإشعارات الفورية الخاصة بالتطبيق تحتاج تطوير Apple Push Notification service وربط الخادم/مزود إرسال وإعداد صلاحيات وشهادة/مفتاح Apple؛ ليست فعالة في هذا المشروع.
- **روابط العودة وتسجيل Facebook/Google:** عودة OAuth التلقائية تحتاج تغيير redirect URI عند مزود الهوية وضبط `sntat://` أو Universal Links. رابط العودة من الويب إلى التطبيق لا ينجح تلقائيًا من غير إعداد الخادم وAssociated Domains؛ بعض مزودي الهوية يرفضون WKWebView، وعندها يجب إضافة آلية `ASWebAuthenticationSession`.
- **مكالمات الصوت والبث:** يتوقف التوافق النهائي على WebRTC وسياسات iOS وإعداد خادم الموقع، ويحتاج اختبار على iPhone حقيقي.
- **النشر على App Store:** يتطلب استيفاء سياسات Apple، ولا يوجد ضمان لقبول أي تطبيق يقتصر على عرض موقع ويب.

## كيف تحصل على IPA وأنت تستخدم ويندوز؟

1. أنشئ مستودع GitHub جديدًا وارفع **محتويات هذا المجلد** إلى جذر المستودع، بحيث ترى `project.yml` ومجلد `.github` داخل الجذر (ارفع المجلد المخفي `.github` أيضًا).
2. افتح تبويب **Actions** في GitHub، ثم اختر **Build SNTAT iOS 9.0.3 IPA** واضغط **Run workflow**. أو اجعل رفع الملفات على فرع main يشغل البناء تلقائيًا.
3. انتظر نجاح Job `Build iPhone app on cloud Mac`.
4. من قسم **Artifacts** أسفل تشغيل الـWorkflow نزّل `SNTAT-v9.0.3-UNSIGNED-IPA`؛ بداخله ملف `SNTAT-v9.0.3-UNSIGNED.ipa`، وهو **غير موقّع**.
5. لتثبيته على iPhone تحتاج توقيعًا صالحًا. تستطيع استخدام أداة توقيع وتحميل جانبي تدعم ويندوز وApple ID الخاص بك، مثل Sideloadly أو AltStore إن دعمت نسختك والجهاز، أو توقيع إصدار توزيع باستخدام شهادات Apple Developer وملف provisioning profile مناسب. تنزيل ملف IPA غير الموقّع إلى الآيفون لا يكفي لتشغيله.

> حساب Apple ID مجاني قد يفرض انتهاء مدة التوقيع التجريبي وتجديده، وقيودًا أخرى. للنشر العام المعتاد استخدم عضوية Apple Developer وإجراء مراجعة/توزيع رسمي.

## الهيكل

- `project.yml`: إعداد XcodeGen لتوليد مشروع Xcode.
- `SNTAT/AppDelegate.swift`: نافذة التطبيق، تشغيل الفيديو وربط العودة.
- `SNTAT/IntroViewController.swift`: فيديو افتتاحية 5 ثوانٍ.
- `SNTAT/BrowserViewController.swift`: واجهة منصة سنتات.
- `SNTAT/Resources/intro_video.mp4`: فيديو النسخة الأصلية.
- `SNTAT/Assets.xcassets`: الأيقونة وشعار شاشة التشغيل.
- `.github/workflows/build-ios-ipa.yml`: بناء IPA على GitHub باستخدام `macos-15`.

## التحقق والأمان

- ملفات Swift مختبرة **نحويًا** بالـSwift parser على Linux، وملفات YAML وXML وPNG وMP4 فُحصت محليًا.
- **لم يُجرَ بناء iOS فعلي باستخدام Xcode ولم تُجرَ تجربة على iPhone من هذه البيئة**. أول تشغيل لـGitHub Actions سيحدد أي أخطاء توافق محتملة.
- لا تضع كلمات مرور Apple أو شهادات التوقيع أو رموز وصول GitHub داخل المستودع العام.
- لا تحاول تحويل APK إلى IPA فقط بتغيير الاسم؛ هذا المشروع يعيد بناء واجهة iOS من المصادر.
